CHAPTER 03 / ELYSIA TECH

桌面座標與輕量物理

如何讓角色跳起、落地或站在視窗上？

基礎概念

螢幕 y 向下增加；每個 tick 更新垂直速度，腳底跨越平台就落地。

艾莉如何實現

DesktopEngine.physics_tick 用 vy = min(vy + gravity, terminal)，預測新腳底位置，確認平台接觸或地板，再限制位置；支援視窗附著和多螢幕。

速度更新 → 預測位置 → 平台判定 → 落地
視窗頂端 / 平台
✿

在平台上，等待事件。

教學示意：簡化 tick 模型。

限制與注意事項 這是輕量 2D 幾何，不是通用物理引擎；特殊視窗可能不適用。

CHAPTER 04 / ELYSIA TECH

自主行為與加權決策

如何讓艾莉不必等待指令也會自己行動？

基礎概念

規則決定必要行為，權重決定其他候選行為的相對機率。

艾莉如何實現

BehaviorEngine 維護 mood、energy、curiosity、boredom、attention、sleepiness；夜晚與閒置會更新狀態。睡意 ≥82 或精力 ≤16 優先睡覺，其他情境以加權抽樣選動作。

時間／使用者活動 → 隱藏狀態 → 規則及加權 → 動作
一般候選：走動、閱讀、待機…

只示範真實的優先睡覺門檻，其餘加權過程省略。

限制與注意事項 這是規則式決策，不是情緒感知模型或強化學習；權重不等於真實情緒。

CHAPTER 05 / ELYSIA TECH

有限狀態機與動畫優先權

如果正在閱讀，使用者突然拖曳她呢？

基礎概念

FSM 保存當前狀態；優先權、鎖定時間與冷卻用來限制狀態轉換。

艾莉如何實現

AnimationStateMachine.can_start 檢查 cooldown 與 locked_until；預設 idle=0、reading=10、dragging=100、falling=90；高優先權可打斷低優先權。

請求動作 → 檢查冷卻與 priority → 切換／拒絕

當前動作：閱讀 reading（10）

假設動作仍在鎖定期且無冷卻。

請選擇動作
限制與注意事項 同優先權也可能通過；此處不宣稱有固定的完整轉移表。

CHAPTER 06 / ELYSIA TECH

應用程式感知

艾莉怎麼知道使用者正在做什麼？

基礎概念

前景程式的名稱及視窗資訊可被分類成使用情境，並不等於理解使用者心思。

艾莉如何實現

ApplicationWatcher 取得 Windows 前景 metadata，profile 分類，防抖避免快速切換造成反覆觸發；前景與允許的 profile 是畫面擷取入口。

前景視窗 → Profile → 穩定情境 → 感知事件
VS Code → 開發情境
瀏覽器 → 瀏覽情境
未知程式 → general

概念分類示意，實際 ID 以 profile 設定為準。

限制與注意事項 普通應用並非一律截圖；畫面擷取受 profile gate 限制，記憶體內處理。

CHAPTER 07 / ELYSIA TECH

電腦視覺：ROI 與模板比對

艾莉怎麼知道遊戲畫面出現結算？

基礎概念

ROI（感興趣區域）縮小搜尋範圍；模板比對找相似圖樣；閾值決定是否接受。

艾莉如何實現

RecognitionEngine 針對 label 呼叫 detector，TemplateDetector 在 ROI 內比對多個尺度；HSV 使用 CCOEFF_NORMED，SQDIFF_NORMED 則轉為 1−raw，最後與閾值比較。

WGC 畫格 → ROI → 比對分數 → 場景證據

限制與注意事項 分數不是校準後的機率；遮擋、縮放、畫質或未知畫面可能辨識失敗。

CHAPTER 08 / ELYSIA TECH

穩定辨識與遊戲進度

一張畫面就能確認真正完成嗎？

基礎概念

時序確認（Temporal confirmation）需要連續且新鮮的證據；UNKNOWN 是安全的不確定結果。

艾莉如何實現

TemporalSceneTracker 使用進出穩定判定；DNAAutoRunMonitor 是唯一進度來源，避免中途每輪誤推播。v2.4c 數字候選需三張新畫面一致並核對生命週期。

場景證據 → 時序確認 → 連戰語意 → 進度
123
0 / 3：尚未確認

僅展示三張新畫面一致的原理，不是完整連戰演算法。

限制與注意事項 數字功能預設關閉；扼守只讀 current、total 無確認；驅離能力仍關閉，完整實機驗收 PARTIAL。

CHAPTER 09 / ELYSIA TECH

角色台詞與互動反應

她說話時一定使用生成式 AI 嗎？

基礎概念

預寫台詞可依分類、語氣、稀有度與冷卻選擇；和 LLM 生成新文字是兩種技術。

艾莉如何實現

DialogueSelector 在 320 條台詞中依 pool 篩選及加權，排除近期句子與冷卻中句子，必要時按規則放寬；ReactionPolicy 可決定台詞、動作或沉默。

情境事件 → 反應政策 → 候選台詞 → 加權選擇

輸入：使用者回到電腦

等待選句

自創示意台詞，排除上一句；不是艾莉的正式台詞庫，也不會呼叫 LLM。

限制與注意事項 v2.4c 未找到 LLM API 實作證據；本作業的 LLM 用於 Wiki，而非桌寵即時語言生成。

CHAPTER 10 / ELYSIA TECH

手機連動、事件與推播

如何離開電腦後仍得知遊戲結束？

基礎概念

事件匯流排解耦生產與消費；HTTP 取快照，WebSocket 傳即時狀態，Web Push 可離線通知。

艾莉如何實現

CompanionEventBus 組合語意事件，MobileLinkService 驗證配對後傳快照及更新；PWA 可透過 Service Worker 接收推播，依規則只通知重要結果。

遊戲事件 → Event Bus → HTTP／WebSocket／Push → 手機

CHAPTER 11 / ELYSIA TECH

設定、隱私與版本限制

功能越多，怎麼避免資料外洩及錯誤？

基礎概念

預設關閉高風險／敏感功能，設定更新時保留未知狀態，不硬猜。

艾莉如何實現

ConfigManager 對 JSON 深度合併並以暫存檔替換；壞檔備份。手機、遠端及推播預設關閉；僅分享語意，畫面不寫入磁碟。

讀設定 → 合併預設 → 驗證／備份 → 儲存
預設關閉 手機 / 遠端 / 推播
僅分享語意 不公開影像與私人欄位
UNKNOWN 資訊不足，不猜結果
限制與注意事項 頭部視線跟隨已移除，舊素材僅備份；LLM／手勢／語音／空中手寫不列為此版已完成。
